# No-code-protection

Бот автопостинга Telegram-канала «Защита Без Кода» — кибербезопасность без VPN-повестки:
уязвимости и патчи, атаки, утечки, вредоносное ПО, фишинг, защита личных данных.

Работает на GitHub Actions: 4 слота в сутки (06/12/15/18 UTC = 09/12/15/18 МСК),
по одному посту за прогон.

## Как получается пост

1. `fetch_rss` / `fetch_youtube` собирают материалы из 20 RSS-лент и 3 YouTube-каналов.
2. `passes_local_filters` отсекает мусор: технообзоры, финансы, казино; нужен хотя бы
   один термин безопасности.
3. `rank_candidates` (в `scripts/post_format.py`) ставит материалы по значимости:
   активная эксплуатация и CVE выше, массовые платформы (Windows, Android, браузеры,
   роутеры, почта, мессенджеры) выше, enterprise-only ниже, свежее выше старого.
   Случайного выбора «первого из перемешанной пачки» больше нет.
4. `is_duplicate` / `is_too_similar_to_recent` отбрасывают повторы сюжета и CVE.
5. `build_prompt` собирает промт, Groq (`openai/gpt-oss-120b`) генерирует пост.
6. `sanitize_post` чистит разметку, `validate_post` проверяет формат и факты.
   Если проверки не прошли — одна повторная попытка с перечнем нарушений.
7. Пост уходит в канал с добавленной строкой «🔗 Первоисточник».

## Формат поста

```
🛡 <b>Заголовок: суть в 6–10 словах</b>

Лид: 1–2 предложения — что произошло, кого касается, чем грозит.

• конкретный факт
• конкретный факт
• конкретный факт

<b>Что делать</b>
• действие
• действие

<i>Одна фраза-вывод.</i>
```

Блоки «Что делать» и вывод необязательны: если в материале нет настоящих действий,
блока нет. Регистрация на вебинар, «ознакомиться с исследованием» и «следите за
обновлениями» за действия не считаются — валидатор их режет.

Разметка: `<b>`, `<i>`, `<code>`, `<blockquote>`. Объём 500–1500 символов.

## Что проверяет валидатор

- длину, наличие заголовка с тематическим эмодзи и `<b>`, разбивку на блоки;
- парность тегов, лимиты `<b>` и `<code>`, длину буллетов и абзацев;
- чёрный список фраз («в источнике не уточняется», «будьте бдительны», канцелярит);
- служебные подписи «Что случилось:», «Лид:» — пост не должен выглядеть анкетой;
- фейковые действия в блоке «Что делать» (вебинар, «следите за»);
- придуманные факты: номер CVE, которого нет в материале, год, которого там нет,
  неправдоподобный номер CVE (больше 5 цифр);
- неразрывные дефисы и пробелы, ссылки, хештеги.

## Файлы

| Файл | Что делает |
|---|---|
| `scripts/kibersos_autopost.py` | сбор материалов, Groq, отправка в Telegram |
| `scripts/post_format.py` | промт, санитайзер, валидатор, ранжирование (без зависимостей) |
| `tests/test_post_format.py` | офлайн-тесты формата и ранжирования |
| `cache_sec/` | состояние: отправленные id, последние посты, бюджет Groq |
| `.github/workflows/kibersos.yml` | автопостинг по расписанию |

## Секреты репозитория

`GROQ_API_KEY`, `TELEGRAM_BOT_TOKEN`, `CHANNEL_ID`.

## Локальный запуск и проверка

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
pytest -q
ruff check scripts tests
```

Сухой прогон без публикации (печатает пост в лог, в канал не отправляет):

```bash
DRY_RUN=1 GROQ_API_KEY=... TELEGRAM_BOT_TOKEN=... CHANNEL_ID=... \
  python scripts/kibersos_autopost.py
```

В Actions — `workflow_dispatch` с включённым флажком `dry_run`.

## Как менять стиль постов

Весь стиль живёт в `scripts/post_format.py`: блок `SYSTEM_RULES` (что требовать от
модели) и константы `BANNED_PHRASES`, `FAKE_ACTIONS`, `TITLE_EMOJI`, `MIN/MAX_POST_LENGTH`.
После правки — `pytest -q`: тесты держат формат, чтобы пост не съехал обратно в
«Что случилось / Где и кого это касается / Почему это важно».

Ограничение по бюджету: 500 000 токенов Groq в сутки (`cache_sec/groq_budget.json`),
этого хватает на 4 поста с запасом на повторные попытки.
